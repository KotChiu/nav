# MotoNav 2.1 — Carbon Racing UI / 配色修订

> 设计分支 `codex/visual-system-redesign-20261110`，基于 `feature/board-2.1` 精确提交 `b3cc3ad8dfb5591e5da8d604049e45ea272721ee`。本改造限于 **2.1 英寸 ST7701S RGB / 480×480 圆屏**，不覆盖原分支的新地图地点标注、滑动优化、手机侧协议或电子吧唧图片传输。当前为 Draft PR #4，**没有通过真实硬件视觉验收**。

## 视觉原则

- **不要像素手表、卡通表情包或赛博霓虹拼贴。** 采用「Carbon Racing / 石墨竞速」：去掉上一版蓝绿色系。整体采用石墨近黑底、石墨灰卡片、暖白正文，少量竞速橙用在选中/进度/主要操作，冰蓝专用于手机连接与天气数据。导航警示仍保留红色语义色。
- **只有一个排版字族：LVGL Montserrat。** 16 / 20 / 24 / 28 / 40 / 48 px 六级；大号 48 px 实时时间或速度。取消 `WatchDigits.c` 像素字体在实际界面的引用。
- **真实信息优先于装饰。** 首页时钟、连接状态、当前温度与天气；天气页当前状况+四格预报；Ride 页真实车速/路程进度；Music 读取手机媒体信息；股票读取真实行情；电子吧唧继续从手机上传图片。
- **圆形安全区域。** 466×466 逻辑坐标，实体显示为 480×480，重要文案和可点控件均位于圆周内，绝不用右下角常规矩形底部导航栏。
- **保护驾驶信息。** 路线、转向、车道、红绿灯和地图仍按原可靠逻辑；靠近路口自动从非导航页回到导航页，视觉修改不改变 BLE 协议和导航数值。

## Settings：实际交互，不是假按钮

| 分类 | 项目 | 触发与状态 |
|---|---|---|
| Display | Brightness | 滑杆 5–180，立即控制背光，松手后延迟写入 `bright` |
| Display | Orientation | 每次点击 **顺时针 +90°**；与现有屏幕转向矩阵共享，已有延迟持久化到 `rotd` 与 `rot` |
| Ride | Minimal map | 切换 `cleanOn`，重绘地图，持久化键 `cleanmap`；手机后续指令可能覆盖本地偏好 |
| Ride | Trip ring | 切换 `progOn`，重绘导航，持久化键 `progring`；手机后续指令可能覆盖本地偏好 |
| Link | Music keys | `HID` 与 `APP` 真实两种模式，执行原有 `#HM` 同款状态清理与持久化到 `mediahid`；手机端模式仍需匹配 |
| Link | Phone status | BLE 已通过认证/等待配对的真实状态 |
| About | Device name / Firmware / PSRAM | 只读，显示真实蓝牙名、固件版本和空闲 PSRAM |

设置页的显示根对象和事件回调集中在 `ui/LvglSettingsPanel.h`；主页/天气/Ride 分别对应独立 LVGL 组件。所有页面按原来的 `PageRoutes.h` 滑动顺序，不篡改触摸算法和旧版路线缓冲。

## 已有兼容性边界

- 导航 **速度/距离/路名/车道/道路覆盖**仍有 Arduino GFX 和手机 4bit 灰度图的绘制历史，避免随意替换安全敏感的地图文字。代码只有把「通用仪表页的本地文字」统一成 Montserrat，并没有谎称所有手机渲染的中文都是 Montserrat。
- 电子吧唧继续保持 232×232 RGB565 图像的原始传输与 2× 展示方式；未做会破坏颜色的有损转换。
- 不合并旧的 LVGL 迁移 PR #2，也不覆写 2.1 功能分支。后续可另行解决两个 PR 的合并冲突。
- 暂未进行真机烧录、外部手机数据实测、0°/90°/314° 触摸坐标对齐、PSRAM 峰值和实体圆屏文字锯齿对比。这些必须在硬件验收后才能签署通过。

## 2026-11-10 二次改造：Map First × Stacked Cards × Vector Icons

这轮落实的原则不是「用抽象仪表代替地图」：**设备真实导航的主画面仍来自 `src/map/MapFrame.h`**，沿用原提交 b3cc3ad 的栅格/矢量底图、路线、地点标注、当前车头、车道、转向、交通灯和提醒，且不会伪造道路和路线。新增 `ui/LvglMapOverlay.h` 仅在上沿左右小面积添加「MAP / SYNC」「LINK / OFF」图标胶囊，直接读取现有地图帧有效性与 BLE 认证状态；`cleanOn`、来电、配对、页面滑动、数据中断时自动隐藏。地图帧状态跨模块通过 `navMapHasFrame()` 查询，不重复维护状态。

- `ui/LvglIcons.h`：16 种原生 LVGL 矢量图标（地图、路线、天气、音乐、股票、设置、屏幕、骑行、连接、照片、方向、充电/电量、涨跌、播放/暂停/切歌等）。线条绘制，所有静态坐标数组拥有全生命周期，不依赖不稳定的 emoji/特殊图标字体；设备不需附加字体文件。
- **Home**：前景固定的 332×245 主要卡片展示真实手机同步时钟、连接状态和天气；背后露出 Ride 与 Markets 两张可点击卡片。由 `LvglOverlay.h` 中相同的真实状态更新，不将卡片等同静态截屏。
- **Stocks**：不再竖向滚动多个 344px 宽卡片，而是在 320×218 范围内一次显示一个真实行情。两张背卡只承担层次感，左/右箭头循环切换 `stockQuotes[]` 中的数据，焦点索引受 `STOCK_MAX` 约束。现有手机下发的中文 4bpp 股票名按比例采样缩放到 164×28，不再直接截掉右侧；价格、涨跌百分比和 280×47 K 线各自有独立宽度且裁切在内部。股票名称与价格使用不重叠的上下两行，避免文字横向互相压住。0 行情显示单张 empty state。
- **Settings**：保留之前实现的 Display / Ride / Link / About 真正可用的设置回调；各分类加图标和两层背卡，活跃卡片仍包含实际亮度、地图开关、行程环和 HID 控件，全部沿用 Preferences 持久化。
- **Music / Weather / Badge**：上一首/播放/暂停/下一首换为可切换的矢量符号；天气圆形展示天气图标；电子吧唧无图时用照片图标。真实手机封面、天气详情和上传图片继续沿用原协议。
- 圆屏几何校验：`ui/CircularCardGeometry.h` 和 `firmware/tests/CircularCardGeometryTest.cpp` 检测主卡、背卡、地图胶囊四角是否位于 466×466 安全圆内，并验证股票名、价格、涨跌、图表都在 320×218 主卡范围。CI 同时跑字体/语义色/UI 静态规范和 ESP32 编译。

> 设计原则是当前卡片聚焦、背卡只露边且能打开对应页面。**导航不采用堆叠卡片**：行驶安全优先，持续显示真实地图；转向、车道、速度不会被大面积弹层覆盖。

**仍需实机检查**：实际地图图形与新图标的遮挡关系、股票中文缩小后的字迹清晰度、触摸卡片选择/方向、PSRAM 消耗、音乐按键和不同屏幕转角。CI 编译与静态几何测试不代替实体 480×480 圆屏测试。


## 2026-11-10 续作：地图状态与市场行情一致性

这部分是**真实固件修复**，仍在 Draft PR #4 上，未合并开发分支。

- 地图首次显示及重新进入时，强制刷新状态胶囊：无有效地图帧显示 SYNC，未认证的手机显示 OFF；矢量图标与文字使用匹配的状态色，不能让默认 MAP/LINK 冒充实时数据。
- 股票列表 #STK 先完整解析，再一次性替换显示列表。被截断的 BLE 指令不会覆盖半张行情表；股票代码改变、列表重排或移除时，清除旧 K 线和槽位绑定的中文名称位图，新中文位图到达前展示真实股票代码。
- K 线 #SK 校验四字段齐全；当周期切换时，先清空所有旧周期走势，再逐股收取新周期图表，避免日 K 和月 K 混合显示。当前协议仍无 generation ID，旧分片迟到的跨周期乱序无法被完全排除。
- 市场同步状态显示设备收到 #STK 以来的真实经过分钟数，明确只是手机推送的接收年龄，不是交易所行情原始时间。离线和超三分钟的过期信息有独立提示。

静态回归约束补充在 tools/ui-audit.py；硬件编译和真实 BLE 压测仍需分别验收。


### Home 触摸面积二次修订

最初的 Wallet 纵向层叠让最底下 Markets 只露出约 18 个逻辑像素，难以在真实圆屏上点中。保留 332×245 的主信息卡，在其下沿改成左 Ride、右 Markets 两张背卡并排露出；**每张都有 49px 高的可见触摸带**，对应页面路由不变，导航仍由手机真实路线驱动。更新 CircularCardGeometryTest 与 UI 审计以检查两张背卡在 466px 安全圆内、不重叠，并且可见高度至少 44px。触控在戴手套及不同旋转角度下是否好用仍需实机验证。


## 2026-11-10 导航统一视觉：Carbon Map HUD

这轮直接在 2.1 固件中完善主导航页面，而不生成替代地图的静态 Mock。

- **保留用户路线和地图算法**：`MapFrame.h` 仍使用手机送来的矢量/栅格底图、真实路线、车头、转弯方向、车道、限速牌、红绿灯、测速点、地名位图。没有新增伪造路径或改变路线预测、蓝牙协议及导航状态机；用户选择的地图主题也不被强行替换。
- **同一字体系统**：`ui/LvglNavSpeed.h` 原生 Montserrat 40/16 车速胶囊，`ui/LvglNavDistance.h` Montserrat 40/28 的真实转向距离，后者复用原有 `distText(navDist)` 单位格式，距离不重复预测。超速变红、接近转弯改暖色；大转向箭头和车道仍由既有原生 GFX 绘制。**原 GFX 车速/距离绘制仍在 LVGL 下层执行，若 LVGL 未渲染，旧绘制可见**。
- **石墨信息层**：上方车速、测速及车道采用统一深色面板、浅边框；下方原来漂浮的转向箭头和数字落入半透明感较弱、但更清晰的 Carbon 深色圆角板，转弯警告/交通标志保留原语义颜色。手机发送的道路名称和 POI 名称改用同一套深色圆角牌，路名背景宽度按圆弧可见区域限制，尽量减少长文案贴边。
- **驾驶优先级**：只有确实处于地图模式才显示 LVGL 地图辅助标签。车道提示进行中、限速牌出现时，MAP/SYNC 和 LINK/OFF 两个非必要装饰胶囊自动隐藏；清爽模式和龙珠雷达模式也隐藏辅助胶囊。真实地图地名布局同步登记胶囊占位，避免新地名卡片被它们盖住。连接身份与地图帧状态继续显示真实数据。
- **可验证边界**：`ui/NavChromePolicy.h` / `firmware/tests/NavChromePolicyTest.cpp` 检查车速、转向、距离牌以及地图辅助胶囊都落在 466px 安全圆内，并断言关键 UI 不被胶囊遮挡；CI 运行 ESP32 固件编译和新增 host test。性能、GFX/LVGL 重绘顺序、日/夜地图对比度、0°/90°/314° 转角与实车导航，依然需要真机确认。

这是视觉层的安全渐进迭代，**尚不是把全部地图转换为 LVGL 原生矢量组件**。后续底层统一应在独立 LVGL 迁移 PR 的性能与实机回归后再进行，不能为了外观直接删掉当前地图绘制器。


## 2026-11-10 首页第三轮：Clock First / 低打扰状态

前两版首页像设备调试台，而不是摩托车仪表。原则改成：**优先显示骑手需要看到的信息，不解释数据如何到达设备**。

- **禁止工程占位**：主页不显示 `TIME FROM PHONE`（旧预览文案）、`SYNC PHONE TO SET TIME`、`WEATHER FROM PHONE` 或大号 `PHONE OFFLINE`。首次启动未有时间时保留明确的 `--:--`，日期区域为空；天气未获取时为 `--°` 和空白预报，不伪造日历或预报数据。
- **明确的视觉层级**：屏幕上方单独有 MOTONAV 标识；主卡左上是手机同步后真实本地日期；中央使用 Montserrat **48px** 真实时间（当前 LVGL 构建支持的最大预置尺寸），通过更大的留白和字距形成视觉焦点。细分隔线下方是一条简短天气行（28px 温度和实况预报）。不再重复品牌/时间来源说明。
- **状态要安静，但不能造假**：右上角只有 8px 颜色点和简短 `LINKED` / `OFFLINE` / `LOST`；连接和丢失状态仍从现有 BLE 认证及 `waitSt` 来，状态颜色绑定真实连接结果，不编造准备就绪。
- **保留实际行为**：Ride、Markets 背卡各露出 49px 的可点击区域，时钟仍走 `clockNowEpoch` / `clockLocalTime`，天气仍用手机下发 `wxHave`、`wxTemp`、`wxFl[]` / `wxFh[]`，页面滑动与导航模式互不干扰。
- **圆屏回归**：`CircularCardGeometryTest` 检查日期、48px 时间、连接点、分隔线与天气区都在 332×245 主卡内；`tools/ui-audit.py` 验证主页没有工程性状态标语、48px 预置字体可用且内容持续绑定真实设备数据。

新样式是固件层面的真实改动，不是实拍效果。字体大小、不同时间字符串宽度、屏幕转角与亮度仍需在实体 2.1 英寸圆屏上核查。
