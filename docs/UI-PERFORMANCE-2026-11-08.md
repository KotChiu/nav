# 2.1 圆屏交互性能实测

设备保存角度为 314°，不是整数 90°。通过串口 UISTAT / DISPLAY 阶段计时核对。

| 方案 | 转换/写入耗时 | 处理 |
| --- | --- | --- |
| 原双线性任意角度路径 | 单次 UI 样本约 138ms | 替换 |
| 行起点 + 定点增量 + 最近邻采样 | 启动帧39–47ms，交互约55–58ms | 保留 |
| 交互2×2采样 | 交互约46–48ms | 收益有限，撤回 |
| 10行RGB bounce buffer | 交互约70–77ms | 变慢，撤回 |

这些是不同场景的阶段计时，不是标准化帧率测试，也不是触摸到显示的端到端延迟。不能据此宣称已经流畅或达到某个固定FPS。

当前保留最近邻采样，斜向文字/细线可能比原双线性路径更锯齿。矩阵增量与原变换的360角度抽样坐标差最大0.00728像素。

外部分析中的LVGL早退、同步降级、整数角度双线性路径属于早期源码，当前已修改。ESP-IDF release/v5.5的rgb_panel_draw_bitmap会检查输入是否属于自身帧缓冲；属于时跳过CPU复制，进行缓存同步，因此“整屏原地复制自己一次”不成立。触摸IRQ极性还需根据CST820实际配置/信号核对，未直接改动。

剩余重点：任意角度局部刷新、页面进入准备耗时、源/目标帧缓冲布局、端到端输入延迟和扫描撕裂。默认亮度仍为70，保留设备已有设置。

随后实机角度切换为0°。撤回bounce实验后，串口确认deg=0，启动全帧复制样本42.3ms（首次）和25.6ms（随后一帧），驱动提交约0.3ms。采集窗口内无滑动帧，不能据此宣称交互帧率或流畅度；0°路径仍有全帧PSRAM复制开销。
